## 3. 통신 방식

### 3.1 REST API (HTTP)

```
Client (React)                    Server (Spring Boot)
      │                                   │
      │──── POST /api/auth/login ────────▶│
      │                                   │
      │◀─── { data: LoginResponse } ──────│
      │                                   │
```

**특징**:
- Axios 인스턴스 사용
- withCredentials: true (쿠키 자동 포함)
- Content-Type: application/json
- 표준 ApiResponse 응답 형식

### 3.2 WebSocket/STOMP (실시간 채팅)

```
Client (React + STOMP)            Server (Spring Boot WebSocket)
      │                                   │
      │──── CONNECT /ws/chat ────────────▶│
      │                                   │
      │──── SUBSCRIBE /topic/chat/room1 ──▶│
      │                                   │
      │◀─── MESSAGE (채팅 메시지) ──────────│
      │                                   │
```

**특징**:
- SockJS 폴백 지원
- STOMP 프로토콜
- 구독 기반 메시지 수신
- 메시지 타입: TEXT, IMAGE, FILE

### 3.3 Socket.IO (시그널링)

```
Client (React + Socket.IO)        Signaling Server (Node.js)
      │                                   │
      │──── join-room { roomId } ────────▶│
      │                                   │
      │◀─── all-users [ ... ] ────────────│
      │                                   │
      │──── signal { sdp, candidate } ───▶│
      │                                   │
      │◀─── signal (from peer) ───────────│
      │                                   │
```

**이벤트**:
- `join-room`: 방 입장
- `signal`: SDP Offer/Answer, ICE Candidate 교환
- `send-message`: 채팅 메시지
- `focus-time-update`: 집중 시간 업데이트
- `room-count-update`: 접속자 수 브로드캐스트
- `user-joined`, `user-left`: 참여자 상태

### 3.4 WebRTC P2P (미디어 스트리밍)

```
Peer A                 Signaling Server              Peer B
  │                          │                          │
  │── join-room ────────────▶│                          │
  │                          │◀──────────── join-room ──│
  │                          │                          │
  │◀─ user-joined (B) ───────│                          │
  │                          │                          │
  │── signal (Offer to B) ──▶│──────────────────────────▶│
  │                          │                          │
  │◀────────────────────────│◀── signal (Answer from B) ─│
  │                          │                          │
  │◀──────────── Direct P2P Media Connection ──────────▶│
  │                          │                          │
```

**구성**:
- RTCPeerConnection
- STUN Server: stun:stun.l.google.com:19302
- addTrack: 로컬 미디어 전송
- ontrack: 원격 미디어 수신

│     - withCredentials: true                                     │

## 7. 확장성 고려사항

### 7.1 수평 확장

| 컴포넌트 | 확장 전략 |
|----------|-----------|
| Frontend | CDN 배포, 정적 파일 캐싱 |
| Backend | 다중 인스턴스 + Redis 세션 공유 |
| Signaling | 다중 인스턴스 + Redis Pub/Sub |
| Database | 읽기 레플리카, 샤딩 |

### 7.2 캐싱 전략

| 대상 | 캐시 위치 | TTL |
|------|-----------|-----|
| 세션 | Redis | 세션 만료 시간 |
| 정적 자원 | 브라우저 | 1시간 |
| API 응답 | Redis (필요 시) | 5분 |
